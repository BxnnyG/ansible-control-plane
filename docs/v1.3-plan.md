# v1.3 plan: load times and UX polish

Source: read-only performance and UX audit of 2026-11-10 (v1.2.0). Branch `feat/v1.3-ux-performance`.
Each item is one commit (Conventional Commits). Tick the box in this file in the same commit.

## Audit findings in short

- Server-side handler times are fine (p50 4-97 ms, max 268 ms). Time is lost in round trips
  (80-400 ms each on the user's network path), serial fetch chains, and static assets that are
  neither cached nor compressed.
- Several pages lack basic comfort features: bulk selection, search, loading skeletons,
  consistent feedback and confirmation dialogs.

## Package 1: quick wins

- [x] P1.1 Cache headers for the embedded SPA (`internal/server/server.go`, static file handler):
      `Cache-Control: public, max-age=31536000, immutable` for `/_app/immutable/*`, `no-cache`
      for `index.html` and every SPA fallback response. Test included.
- [x] P1.2 Compression for JS, CSS, JSON, SVG and HTML (chi `middleware.Compress` or equivalent).
      SSE routes (`text/event-stream`) must stay uncompressed and unbuffered. Test included.
- [x] P1.3 Session bootstrap (`web/src/lib/session.svelte.ts`): do not run `me`, `workspace`,
      `setup` strictly in sequence. Fetch in parallel where the stored workspace slug allows it and
      do not block `ready` on the setup status (the setup redirect may happen late).
- [x] P1.4 Template detail (`web/src/routes/templates/[id]/+page.svelte`): load template, refs and
      recent runs with one `Promise.all`; skeleton while loading; error state with Retry.
- [x] P1.5 Templates list (`web/src/routes/templates/+page.svelte`, `web/src/lib/templateData.ts`):
      load secrets and vault identities only when the form opens.
- [x] P1.6 Fleet (`web/src/routes/fleet/+page.svelte`, `fleet/unmanaged/+page.svelte`): load
      immediately on mount, debounce only the search text; fetch networks once and pass them to
      `NetworkTrackingPanel` as a prop.
- [x] P1.7 `web/src/lib/components/ListSkeleton.svelte` is an empty file: implement it on top of
      `Skeleton.svelte` (table-shaped rows) and check that every list page renders it.
- [x] P1.8 Network picker: one shared component used by the fleet page, settings and the setup
      wizard. Filter box (CIDR, description, VLAN, connector), groups per connector with a
      tri-state group checkbox, "Select all / none / invert" acting on the filtered set, an
      "n of m selected" counter, untracked networks selectable without extra toggles, Save
      disabled when nothing changed. The backend (`POST /networks` with `track_only` or
      `ids` + `tracked`) already supports this. Pure selection logic goes into a tested `.ts` module.
      On the fleet page the network card grid becomes a collapsible compact section.
- [x] P1.9 Fleet wording: nav label "Hosts" (route stays `/fleet`), subtitle that explains the
      page ("Every machine your connectors have seen, merged into one list, with online, Ansible
      and alert status."), empty states with an "Add connector" action, one title scheme for the
      sub-pages. Update `docs/connectors-and-fleet.md`.

## Not in scope

- Network latency between browser and server (overlay network).
- TLS key type (RSA 4096 to ECDSA) and per-request auth query caching: measured cost is small.

`check`, `test`, `build`. Then backup, deploy, smoke check, `HANDOFF.md`.
